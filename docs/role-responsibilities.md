# 쉼표 MVP A/B 역할 분담

## 1. 역할 분담 원칙

- A는 **서비스 구현과 통합**을 담당한다. Frontend 전체, DB, 일정·기상·지도·경로 기능, A/B API 통합이 A의 책임이다.
- B는 **분석과 판단 로직**을 담당한다. 데이터 분석, AI 위험 판단, 노출시간 계산, 쿨링스팟 선정, 기록·집계 로직이 B의 책임이다.
- Backend는 FastAPI로 구현하며, 각 담당자는 자신이 맡은 기능의 API와 명세를 함께 작성한다.
- DB 스키마와 실제 DB 구현은 A가 전담한다. B는 저장하거나 조회해야 할 데이터 요구사항과 저장 로직을 정의하고, A가 제공한 DB 구조에 연결한다.
- A와 B는 합의된 요청·응답 형식을 기준으로 독립 개발하고, A가 최종 서비스 흐름을 통합한다.
- Claude Code와 Codex는 구현·검토에 활용하되, 생성된 코드와 API 명세의 정확성은 해당 담당자가 확인한다.

MVP 핵심 흐름은 다음과 같다.

```text
방문대상자 mock 데이터 생성
→ 오늘 일정·폭염 상태 확인
→ 이동구간 생성
→ AI 폭염 위험 판단
→ 휴식 필요 여부 결정
→ 쿨링스팟 탐색·선정
→ 일반경로·안전경로 비교
→ 방문 진행·기록 저장
→ 노출시간·휴식현황 집계
```

## 2. A 담당 업무

### Frontend 전체

- 일정, 홈, 지도 화면 구현
- 기상·폭염 정보 표시
- 일반경로와 안전경로 표시 및 비교
- 쿨링스팟, 위험도, 휴식 필요도 표시
- 위험판단 근거 팝업
- 방문 완료 처리 및 업무 완료 요약 UI

### DB 전체

- 전체 DB 설계 및 구현
- 방문대상자, 일정, 이동구간, 쿨링스팟 데이터 구조
- 위험판단 결과, 방문·휴식 기록, 업무 결과 데이터 구조
- B가 요청한 기록·집계 데이터의 저장 및 조회 기반 제공

### 일정

- 방문대상자 8명 mock 데이터 생성
- 일정 CRUD와 오늘 방문 일정 조회
- 방문 완료 처리와 다음 방문지 결정

### 기상

- 기상청 및 기타 기상 API 연동
- 현재 기온·습도·체감온도 조회
- 방문 예정 시간대 기상정보 및 폭염 영향예보 조회
- 외부 API 오류·지연 처리

### 지도·경로

- 지도 API 연동과 일반경로 생성
- 이동거리, 예상 도보시간, 예상 도착시간 계산
- 지도 표시용 경로 좌표와 이동구간 데이터 생성
- 쿨링스팟별 경로 이탈거리와 추가 이동시간 계산 결과를 B에게 제공

### 안전경로

- B가 선정한 쿨링스팟을 경유지로 사용
- `현재 위치 → 쿨링스팟 → 다음 방문지` 경로 생성
- 일반경로와 안전경로의 거리·시간 비교
- 추가 거리·시간 계산 및 Frontend 표시용 데이터 구성

### 통합

- Frontend와 FastAPI 연결
- A/B 담당 API 연결과 전체 서비스 흐름 구성
- 통합 테스트 및 시연 가능한 상태 관리

## 3. B 담당 업무

### 데이터 분석

- 체감온도, 기온, 습도, 노출시간 관련 기준 조사
- WBGT 기반 학습 데이터 또는 합성 라벨 구성
- 이동구간 위험 판단 변수 선정과 위험점수 기준 분석

### AI 모델

- 회귀모델 학습 및 0~100 위험점수 추론
- 위험점수를 `안전 / 주의 / 휴식 필요` 3단계로 변환
- 구간별 휴식 횟수를 0~1회로 매핑
- 모델 성능 평가와 테스트 시나리오 구성

### 노출시간

- 일정 기반 계획 시뮬레이션으로 연속 야외노출시간 계산
- 다음 이동 완료 후 예상 노출시간 계산
- 방문지 체류, 쿨링스팟 휴식, 휴식 미이행에 따른 시간 처리

### 위험판단 Backend

- AI 추론을 FastAPI 기능으로 구현
- 이동구간 입력을 받아 위험점수와 3단계 라벨 반환
- 휴식 필요 여부, 주요 위험요인, 판단 근거 반환

### 쿨링스팟

- 공공 무더위쉼터와 기업 쿨링스팟 mock 데이터 가공 및 형식 통합
- 운영시간, 도보 이동, 경로 이탈거리, 추가 이동시간 기준 필터링
- `방문 예정시간 + 5분 버퍼` 조건 적용
- 모든 조건을 만족하는 후보 중 최적 1곳 추천
- 추가 이동시간이 2분 이내로 비슷하면 편의시설이 많은 곳 우선
- A가 지도 API로 계산한 이탈거리·추가 이동시간을 사용하며, B가 지도 API를 직접 계산하지 않음

### 기록·집계

- 방문·휴식 기록 저장 로직과 휴식 이행·미이행 처리
- 하루 누적 야외노출시간, 총 휴식시간, 휴식 횟수 집계
- 업무 완료 시 결과 요약 데이터 생성
- 필요한 저장 필드를 A에게 전달하고 A의 DB 구조를 사용

## 4. 공동 결정 사항

구현 전에 아래 항목을 A와 B가 함께 확정한다.

- A → B 입력과 B → A 출력의 필드명, 타입, 단위, 필수 여부
- 시간대와 일시 형식, 위치 좌표 형식, 거리·시간 단위
- 위험점수 구간과 3단계 라벨 기준
- 휴식 필요 조건과 휴식 완료·미이행 판정 기준
- 쿨링스팟 필터 기준값과 후보가 없을 때의 처리
- 공통 오류 응답 형식과 외부 API 장애 시 대체 동작
- 통합 테스트 시나리오와 완료 기준

공동 결정은 담당 중복을 뜻하지 않는다. 합의 후 UI·DB·지도·통합 구현은 A, 분석·판단·추천·집계 로직은 B가 책임진다.

## 5. A ↔ B 데이터 흐름

### A → B

A는 일정·기상·지도 결과를 결합해 다음 데이터를 B에게 전달한다.

- 출발지와 도착지
- 이동거리와 예상 도보시간
- 예상 도착시간
- 기온, 습도, 체감온도
- 시간대별 기상정보
- 기존 이동경로 정보
- 쿨링스팟별 경로 이탈거리와 추가 이동시간

### B → A

B는 전달받은 데이터를 분석해 다음 결과를 반환한다.

- 현재 및 예상 연속 노출시간
- 0~100 위험점수
- 위험 라벨
- 휴식 필요 여부
- 주요 위험요인과 판단 근거
- 휴식이 필요한 경우 최적 쿨링스팟 1곳

### 휴식 필요 시 처리 순서

1. B가 운영시간과 이동 조건을 모두 만족하는 후보를 필터링하고 최적 1곳을 선정한다.
2. A가 선정된 쿨링스팟을 경유지로 설정해 안전경로를 생성한다.
3. A가 일반경로와 안전경로를 비교해 Frontend에 표시한다.
4. 사용자의 휴식 이행 결과는 B의 기록·집계 로직으로 전달하고 A의 DB에 저장한다.

## 6. 각자 API 명세 작성 범위

각 담당자는 구현 전에 자신의 API에 대해 endpoint, HTTP method, 요청·응답 예시, 오류 응답을 작성하고 FastAPI `/docs`에서 확인할 수 있게 한다.

### A 작성 범위

- 방문대상자 및 일정 CRUD·오늘 일정·방문 완료 API
- 현재 및 예정 시간대 기상·폭염 정보 API
- 지도, 일반경로, 이동구간 생성 API
- 경로 이탈거리·추가 이동시간 계산 API
- 쿨링스팟 경유 안전경로 및 경로 비교 API

### B 작성 범위

- 현재·예상 연속 노출시간 계산 API
- 이동구간 위험분석 및 AI 추론 API
- 휴식 필요 여부와 판단 근거 API
- 쿨링스팟 필터링·추천 API
- 방문·휴식 기록 처리 및 일일 집계·요약 API

## 7. 개발 시 책임 경계

| 영역 | 최종 책임자 | 경계 |
| --- | --- | --- |
| Frontend | A | B는 필요한 결과 데이터만 제공하며 UI를 구현하지 않는다. |
| DB | A | B는 필요한 필드를 요청하지만 스키마와 DB 구현을 직접 변경하지 않는다. |
| 일정·기상 | A | B는 A가 제공한 일정·기상 데이터를 분석 입력으로 사용한다. |
| 지도·거리·경로 | A | B는 지도 API를 직접 호출하지 않고 A의 계산 결과를 사용한다. |
| 위험분석·AI | B | A는 모델 내부 기준을 재구현하지 않고 B의 API 결과를 표시한다. |
| 노출시간 | B | A는 일정·이동·휴식 원천 데이터를 제공한다. |
| 쿨링스팟 선정 | B | A는 후보별 지도 계산을 제공하고 최종 선정 결과로 경로를 만든다. |
| 기록·집계 로직 | B | A는 저장 구조를 제공하고 B의 결과가 DB에 연결되도록 통합한다. |
| 전체 통합·테스트 | A | B는 담당 API와 테스트 시나리오를 제공하고 오류 수정에 참여한다. |

담당 경계를 바꿔야 할 때는 코드를 먼저 수정하지 말고 요청·응답 및 DB 영향 범위를 합의한다. 상대 담당 영역의 파일을 변경해야 한다면 작업 전에 공유한다.

## 8. 최종 역할 한 줄 요약

- **A:** 사용자가 보는 화면부터 일정·기상·DB·지도·경로와 전체 통합까지 서비스 실행 기반을 책임진다.
- **B:** 데이터를 바탕으로 위험과 노출시간을 계산하고 휴식·쿨링스팟을 판단하며 기록 결과를 집계한다.
